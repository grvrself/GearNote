# GearNote

GearNote（简称 GN）是 Tauri 2 + React + TypeScript + Vite 的桌面知识工作台原型。已接入浏览器扩展捕获网页文章与现有视频字幕、本机保存、右栏查看，以及基于已保存资料的 Agent 问答。沿用原应用标识 `com.knowflow.desktop` 和本地数据文件名，以读取更名前的资料、笔记与设置。

## 界面风格

在桌面程序「设置 → 界面风格」可切换原有工业 HUD 与简约黑白主题。黑白主题使用灰阶面板、圆角控件和五种原创线框齿轮图标；主题选择保存在本机，并同步到置顶小窗。切换只影响显示，不改变资料、会话、Agent 或捕获操作。

## 使用 Agent

1. 在桌面程序「设置 → Agent 服务」填写兼容 OpenAI Chat Completions 的 API 地址、模型 ID 和 API 密钥并保存。OpenAI 官方 API 地址为 `https://api.openai.com/v1`；其他服务商按其文档填写。
2. 在右栏展开真实保存的文章或带字幕视频，点击「加入本轮参考」。卡片会显示「本轮参考」标记，提问框上方会显示一行已选摘要；展开后可查看完整标题、定位或移除。失败记录和演示资料不能用于问答。
   也可以在当前会话的一条消息气泡中点击「选此消息为参考」，最多选 4 条。提问框会逐条显示所选消息的文字预览，并允许定位或移除；成功发送后清空这组临时选择。选中的旧消息即使已经被对话压缩覆盖，仍会以标明「用户消息」或「Agent 回答」的 `[对话1]` 类摘录进入本轮上下文。引用可定位回原消息；Agent 回答仅证明对话中曾这样说，不自动成为已核实的外部事实。
3. 在中栏输入问题，按 `Ctrl + Enter` 或点击「发送」。模型正文会逐步显示；回答中的 `[1]` 等编号只对应本轮提供的文章或字幕片段，对话摘录使用 `[对话1]`，图片不占数字编号。下方来源按钮可定位文章、字幕时间点或对话原消息。输入区的「总结」使用同一资料选择。

输入问题后可点击「本轮上下文」查看发送前预览。预览与实际发送共用 Rust 的上下文组装模块，列出人格与回答规则、近期对话、选中的文章或字幕片段和文本字符用量。文章按段落与句子边界切段，字幕以单条为检索单位并附前后两条上下文；选段按词的稀有度和长度评分，同一资料最多取 3 段。问题与资料没有词汇重叠时，会选开头、标题行和结尾，并在预览中标明「覆盖式选取」。文本上限默认 24000 字符，可在设置中切换到 48000 字符；这是长度控制，不是精确的模型 token 数，图片另计。每轮最多选 8 个资料片段，最近 4 条对话单条最多 1500 字。较早对话达到自动压缩阈值时，发送前会调用当前模型生成摘要；原消息仍保存在数据库中，后续请求用摘要和最近的原消息组装上下文。摘要属于背景，不能代替可引用资料。截帧指令不调用模型，因此不显示上下文预览。

开启资料探索且本轮有可用资料时，发送前预览显示标题、类型、网址、字幕时间范围与片段短预览；尚未读取的正文不进入初始请求。模型可用 `search_references` 定位片段，再用 `read_reference` 取得原文和引用编号。回答的工作过程会列出实际读到的标题、时间与编号；若模型没有调用工具，问答回退到通常的预选正文。目录篇幅受限，未列出的片段仍可通过搜索定位。带截图或显式选中对话消息的提问沿用原问答路径，以保留图片处理和对话消息引用。单独选中一条已完成字幕提取的视频时，可在提问框开启默认关闭的「深度模式」。它按字幕顺序分批阅读，每批最多 3000 字、每轮最多 4 批，最多 32 批或 120 秒；整条视频总结会尽量读完整段。回答旁显示实际读到的时间和批次数，未读完时明确显示停止原因。回答的原句仍须来自实际读过的字幕批次。普通资料探索和文章问答不受影响。

有资料依据的回答仍会流式显示，但保存前会在本地逐行检查：每条结论须附对应片段的连续原文引句和编号；对不上的引句、未提供的编号或没有引句的编号都会拒存。资料确实不足时只保留以「资料不足：」开头的一句说明。校验失败会保留原问题供重试。原句校验只证明引文存在于该片段，不能自动判断结论的推理是否正确。

提问区默认只显示一行「本轮参考」摘要；点击可展开资料和消息的完整列表并移除。提问区不再提供「会话管理」面板，也不显示手动压缩、会话计划和默认项目记忆的编辑入口。旧数据仍留在本地数据库；已有的计划和已确认记忆若有内容，仍会进入问答上下文，并可在发送前的「本轮上下文」中查看。

每条新回复会在聊天区显示本轮执行耗时，并可展开查看实际保存的资料探索步骤与文件改动。当前 Agent 尚未开放项目文件写入，因此文件改动显示为无；历史回复没有计时数据时不会推算耗时。

正常问答结束后，GearNote 会使用当前模型额外请求一次后续提问建议，并在最新回复下方显示可选按钮。点击按钮只会将完整问题填入输入框，用户可修改后再发送；画面截取命令不生成建议。若建议请求失败，原回答仍会保存。建议与回复一同保存在本机会话中；这项自动请求会增加 API 用量。

开启资料探索并选有可读资料时，模型若发现方案会明显分叉且用户还未表态，可以通过 `request_choice` 暂停问答，给出 2–4 个单选方案。选择题只显示问题、原因和选项，不同时生成方案正文，也不会修改笔记、资料或会话计划。点击选项会发送「选择：选项名称」；直接输入自己的想法也可回答。成功完成下一轮问答后，会话保存选中的选项 ID 或原文，并要求模型按这次选择继续，不再重复提问。推荐标记仅供参考，不会自动选中。旧会话没有选择题字段时仍可读取。选择题与上方回答后的普通追问建议是两种不同交互。

### 资料探索（第三阶段首个切片）

「设置 → Agent 服务」中的「资料探索」默认开启，可随时关闭，设置保存在本机并同时作用于主窗口和小窗。有已选参考资料的文本提问中，模型最多进行 3 轮决策、6 次只读工具调用，在**本轮已选且处理成功的资料**里搜索片段并读取原文，再流式生成回答。回答中的「资料探索」折叠区保留搜索与读取步骤；来源编号仍可定位到对应记录或字幕时间点。该模式会增加模型请求次数、等待时间和 API 用量。图片提问与指定时间截帧暂不使用此模式。

工具记录会显示搜索命中数、读取的资料标题和对应来源编号。若模型在回答中写入本轮没有提供的数字来源编号，回答不会保存，提问框会保留原问题供重试。编号校验仅核对映射关系，不能自动判断模型的文字结论是否忠实于资料。

在「设置 → Agent 服务」可点击「测试已保存配置」检查资料探索兼容性。该测试只发送程序生成的虚构资料，不读取资料库或写入会话；可能产生少量模型 API 用量。结果显示搜索、读取是否实际调用及耗时。此测试不能替代用真实资料检查答案内容和引用准确性。

DeepSeek 的 Chat Completions 默认启用思考模式，而强制调用工具需要非思考模式；GearNote 在 DeepSeek 资料探索请求中明确关闭思考模式，普通问答不受影响。若服务拒绝强制调用，首轮会用自动模式重试；兼容性测试会显示未调用工具时的回退原因。

发送前的「本轮上下文」仅预览初始内容，不包含模型随后读取的片段；探索模式会为后续工具消息预留 7000 字符，其中工具输出最多 4000 字符。常见的工具调用不支持错误会提示并回退到原有的单次问答；其他服务端错误会直接显示。此能力仍需用实际配置的模型服务做端到端验收。

### 整理为笔记

带真实资料引用的 Agent 回答下方会出现「整理为笔记」。点击后进入「资料库」中的可编辑草稿；核对标题、正文及来源后点击「保存笔记」。草稿可追加到已有笔记，保存后的笔记可导出 Markdown。来源会保留原网页链接，视频引用还会标出时间点。笔记保存在本机应用数据目录的 `knowflow.db`，导出文件保存在其 `exports` 子目录。切换页面时，当前窗口中的未保存草稿会保留；关闭程序前请保存。

资料库左侧支持一级笔记文件夹，可查看全部笔记、未分类或某个文件夹，并可新建、重命名和删除文件夹。编辑笔记时在「文件夹」下拉框选择归属，再保存；从某个文件夹新建笔记会默认归入该文件夹。旧笔记自动显示为未分类。删除文件夹会将其中笔记移至未分类，正文和来源仍保留。文件夹只是应用内分类，不会在磁盘上新建同名目录；Markdown 导出位置不变。

第五阶段已加入笔记正文的可控修改流程。选中已保存笔记，展开「Agent 修改建议与操作记录」，填写修改要求后生成建议；笔记标题、正文和要求会发送给当前配置的模型。模型一次最多提出三处追加或明确原文替换，服务端要求完整 JSON，并在保存前逐项校验；任何一处无效都会整份作废。按资料修改时，仅发送笔记关联且处理成功的资料片段，每处建议必须附可在对应片段中找到的原句。模型不能修改标题、来源或直接写入。界面展示原文位置、新文字和理由；只有点击「确认并写入」才会修改笔记。确认、放弃、过期和撤销会写入本地操作记录；如果笔记后来又被修改，旧建议和撤销会被拒绝。当前仅支持正文不超过 12000 字的笔记生成建议。文件编辑、外部命令及通用模型写工具尚未开放。

旧版生成的会话计划提案与操作记录仍保留在本地数据库中；当前聊天界面不再显示这些提案，也不再提供确认、放弃或撤销入口。

模型请求由 Rust 端发送。问答时会发送本轮问题、选中的资料片段、近期对话，以及已有内容的项目记忆、会话计划和较早对话摘要；自动压缩也会向当前模型发送相关对话。回答后的自动建议请求只发送本轮问题与回答的截短文本。Windows 版会使用当前用户的 DPAPI 加密 API 密钥，存于本机 `agent-key.bin`，重启后自动读取；密钥不会明文写入 `agent-config.json` 或显示在输入框里。地址和模型 ID 存于本机 `agent-config.json`。其他平台目前仍只在本次运行期间保留密钥。会话、消息和每个会话的参考资料存于本机 `knowflow.db`，主窗和小窗共用。首次启动新版时，会从旧 `chat-sessions.json` 或 `chat.json` 迁移，旧文件保留。请求失败会保留输入框内容并显示错误，不会伪造回答。

### 本地存储与旧会话数据

旧会话中若已保存「会话计划」，其目标、已完成事项和下一步仍保存在数据库中。成功保存笔记、捕获文章或字幕、完成视频画面分析等操作，仍可能在旧目标下追加完成记录；失败操作不会追加。聊天界面已移除该计划的编辑入口。

资料、笔记、会话已从旧 JSON 文件迁移至 SQLite `knowflow.db` 的逐条表。首次升级已有数据库前，应用会在同一数据目录生成 `knowflow.pre-phase4.db` 备份；旧 JSON 文件和旧快照保留，但新版不再更新快照，后续修改以逐条表为准。右侧历史栏每页查询 20 条资料摘要，支持类型、标题、网站、正文与字幕搜索；展开记录时才读取完整内容。视频记录可按关键词与起止时间检索精确到秒的字幕。聊天、小窗和笔记来源只接收资料摘要，Agent 提问只复制本轮选中的完整资料。资料与笔记保存采用单项写入；会话和消息仍保留内存状态，但数据库只更新发生变化的行。旧版程序不能可靠读取升级后的新修改；回退时应恢复备份及匹配版本。模型地址、加密密钥、人格文件及视频画面文件仍分别保存。

### 会话列表

左栏会话区以紧凑标题列表显示，可新建、搜索、切换和删除会话。首次回答成功后，「新会话」会按第一条问题自动命名。每条会话分别保存消息与参考资料；右栏资料库由所有会话共用。追问会附带当前会话最近 8 条消息帮助理解语境，但事实引用只允许来自本次选中的资料。删除会话前会要求确认，删除最后一条后会自动创建空会话。窄窗口下点击左栏的会话图标打开列表。原快捷操作中的快捷键说明位于「设置 → 快捷键设置」，查找记录仍可按 `Ctrl + K`；小窗入口在右栏筛选行。

### 人格文件

在「设置 → 人格文件」可直接修改 Agent 的称呼和表达风格，点击「保存人格」后从下一次提问生效。默认人格是严谨、克制的知识管家，会自然地称呼用户为「先生」。点击「载入默认草稿」只修改编辑区，仍需点击保存；「撤销修改」可恢复上次保存的内容。

人格内容保存在本机应用数据目录的 `persona.md`。也可用文本编辑器修改该文件，再回到设置页点击「从文件重载」。人格文件控制表达方式，资料引用规则仍由问答程序约束。进行中的请求使用发送时已保存的人格快照。

### DeepSeek 返回 HTTP 400

如果使用 DeepSeek V4.1 Flash，API 地址填 `https://api.deepseek.com`，模型名称填 `deepseek-flash`。`DeepSeek-V4.1-Flash-1017` 是版本展示名，不能直接作为 API 的 `model` 参数。新版在这种配置下会给出明确提示；其他服务端错误会显示响应中的错误原因。修改设置后重新发送原问题即可。

## 捕获网页文章与视频字幕

1. 安装并打开 GearNote；从源码开发时在项目目录运行 `npm run tauri dev`。
2. 点击应用左侧「设置」，在「网页文章捕获」区复制本机配对码。
3. 点击设置里的「打开扩展文件夹」。Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。开启「开发者模式」，点击「加载已解压的扩展」，选择打开的 `extension` 文件夹。
4. 打开 GearNote 扩展的「扩展程序选项」，粘贴配对码，点击「连接本机程序」。
5. 打开网页文章，或打开带字幕的 YouTube / Bilibili 视频，点击浏览器工具栏中的 GearNote 扩展图标。扩展图标出现 `OK` 后，资料会进入桌面程序右栏。再次点击已保存的资料不会重复创建记录。

资料保存在 Tauri 应用数据目录的 `knowflow.db`。旧 `records.json` 与更早的 `articles.json` 会在首次启动时迁移；`records.json` 会保留作旧版备份，更早的 `articles.json` 会先沿旧版迁移流程改名为 `records.json`。桌面程序右栏只显示本机保存的真实资料；纯浏览器前端预览会显示样张。展开文章可阅读已保存正文；展开视频可查看字幕、字幕时间点及字幕语言。配对码保存在同目录的 `extension-pair-code.txt` 和浏览器扩展本地存储中。

视频必须有播放器提供的字幕轨道；无字幕时右栏会记录失败原因。Bilibili 的部分字幕需要先登录；若字幕提取失败，在视频页再次点击扩展图标可重试。YouTube 与 Bilibili 的播放器内部接口可能变化，届时失败记录会显示原因。需要语音识别的无字幕视频和结构特殊的网页仍待后续阶段。实际捕获动作由浏览器扩展图标触发。

### 视频画面分镜（首版）

展开已捕获的视频记录，点击「分析画面」。GearNote 调用内置的 dsh-video-storyboard 命令行引擎，从可访问的视频链接获取画面，生成最多 4 张分镜图及每格时间范围；结果保存在应用数据目录的 `storyboards/<记录 ID>/`，记录索引写入 `knowflow.db`。点击分镜时间点可在默认浏览器打开原视频。字幕捕获与画面分析分别进行；分镜拼图不会自动发送给模型。

在对话中只引用一条视频后，可以输入「截取 01:20 的画面」或「截图 01:02:20」。这是本地指令，无须配置模型 API；GearNote 会优先复用画面分析留下的视频缓存，再从指定时间取一张 JPEG，作为图片消息保存在当前会话。点击图片下方的「加入提问」并发送问题后，GearNote 才会将该 JPEG 随问题发送至当前配置的模型服务；该模型必须支持 OpenAI 兼容的视觉输入。图片提问会产生模型服务费用，纯文本提问不附带图片。若 B 站限制匿名取流且本机没有视频缓存，需先在记录栏使用登录态完成一次画面分析。

此功能需要 Node.js、`ffmpeg`、`ffprobe` 和 `yt-dlp`。Windows 安装包内含这四个工具，无须单独安装或修改系统 PATH。源码开发时也可使用系统已安装的工具。分析只适用于能够正常访问的视频；取流失败会在卡片中显示原因。画面分析会下载视频并占用本地磁盘空间；扫描缓存与视频下载缓存均放在 GearNote 的应用缓存目录 `video-storyboard` 下，视频下载缓存由分镜引擎按其缓存策略清理。项目源码位于 `vendor/dsh-video-storyboard`，按 Apache-2.0 许可证保留原作者 LICENSE 与 NOTICE。

B 站返回 HTTP 567 时，GearNote 会先用较低画质重试一次。仍需登录的内容可在出错卡片中主动选择仅含 B 站域名的 Netscape 格式 `cookies.txt` 再试。该文件包含登录凭据，请勿分享或放入源码仓库；GearNote 仅在本次分析中创建临时副本，任务结束后删除。浏览器扩展本身不会自动读取或上传登录 cookie。登录凭据过期、会员权限不足或站点限制时，仍可能无法取流。

### Bilibili 字幕匹配修复

旧版使用的 `/x/player/v2` 可能返回其他视频的字幕，即使响应中的 BV 号和 CID 看起来正确。新版改用 `/x/player/wbi/v2`，并核对页面 BV 号、当前分 P 的 CID、响应中的身份字段，以及字幕文件地址中的 CID。任何一项无法确认都会拒绝保存字幕，并在右栏显示失败原因。

新版首次打开时，会把此前保存但未验证来源的 Bilibili 视频字幕标为「提取失败」并移除错误正文；记录标题和网址会保留。关闭旧版程序、打开新版程序，在原视频页重新点击扩展图标即可覆盖这条记录。浏览器扩展也必须在扩展管理页点击「重新加载」。如果字幕地址未包含 CID，新版会选择失败提示，避免把不相关字幕作为正确结果。

### Bilibili 专栏正文修复

旧版可能把会员提示、页面标识和底部文案混入 `/opus/` 专栏正文。新版只从文章正文容器读取文字；若正文尚未加载会提示重试，不会抓取整页。先关闭旧桌面程序并打开新版，再在浏览器扩展管理页点击「重新加载」。回到原专栏页等待正文显示，点击扩展图标重新捕获。旧记录会在原位置更新，保留记录 ID 和对话引用。旧的错误文字在重新捕获前仍会显示。

## 在 Windows 上预览

在此文件夹打开 PowerShell：

```powershell
npm install
npm run tauri dev
```

首次运行可能编译 Rust 依赖。只看前端时运行 `npm run dev`，浏览器访问 `http://127.0.0.1:1420/`。浏览器预览没有原生窗口控制；请使用 Tauri 程序检查标题栏按钮。

给其他人试用时，发送 `src-tauri/target/release/bundle/nsis/` 中生成的 `GearNote_0.1.0_x64-setup.exe`。安装后在设置里点击「打开扩展文件夹」即可加载浏览器扩展。首次运行需在设置中填写自己的模型服务地址、模型名和密钥；资料与配置均保存在试用者自己的本机。安装包未经代码签名，Windows 可能显示来源确认提示。无字幕视频目前不能转写；浏览器扩展只捕获播放器已有字幕。打开新版前请先关闭旧版；两个版本同时运行会占用相同的本机扩展连接端口。浏览器扩展有源码改动时，需在扩展管理页重新加载。

制作 Windows 安装包：在 `.release-tools/` 放入 `node.exe`、`ffmpeg.exe`、`ffprobe.exe`、`yt-dlp.exe` 和对应的 `FFmpeg-LICENSE.txt`、`FFmpeg-README.txt`、`yt-dlp-LICENSE.txt`，然后运行 `powershell -ExecutionPolicy Bypass -File scripts/build-windows-release.ps1`。也可给脚本传 `-NodeExe` 和 `-ToolDirectory`，从指定位置复制这些工具。二进制工具与生成的安装包不提交到 Git；发行时保留安装包内的许可文件。Node 版本须与 `licenses/Node-LICENSE-24.15.0.txt` 对应。

## 目前可操作的部分

- 右栏类型筛选、标题或来源搜索、记录展开、时间点选择和参考资料增删。
- 四种处理状态样张：字幕提取、摘要生成、可提问、提取失败。
- 故障卡片展示原因。视频失败后可在原页面再次点击扩展图标重试。
- 顶栏可以切换浏览器选项，并显示扩展连接状态。捕获说明入口展示扩展安装和配对步骤。
- Tauri 窗口使用无边框标题栏，可拖动、最小化、最大化或还原、关闭。
- 中栏可以移除本轮引用、展开或收起历史记录、发送问题，并从回答来源定位到右栏对应字幕时间点。
- 左栏包含导航与快捷操作。查找记录和 `Ctrl K` 会聚焦右栏搜索；文章与视频捕获说明入口打开扩展安装步骤；快捷键设置入口显示当前绑定。配置 Agent 并添加参考资料后可使用总结命令。
- 顶栏和左栏可打开独立置顶小窗。再次点击会唤回同一窗口。主窗与小窗同步本轮引用；在小窗点击字幕引用会回到主窗并定位对应记录和时间点。
- 小窗沿用中栏组件和 token，以 `body[data-window="mini"]` 呈现紧凑布局，并同步真实对话。

- `VISUAL_GUIDE.md`：本阶段视觉规则与验收范围。
