# GearNote 高级笔记：产品与实施方案

状态：实施中；核心流程已落地，待正式窗口与真实资料验收
日期：2026-11-14
适用代码：以当前工作区为准；撰写时 HEAD 为 eef9c64

> 2026-11-15 实施进度：已有笔记的离线美化、两种主题、截图持久附件、从已选资料生成有引句的草稿、旧笔记整理提案与撤销、自包含 HTML/PDF 导出已接入。自动化测试使用临时数据库与合成图片；阅读样稿也使用合成内容。正式 Tauri 窗口在隔离数据目录下未能启动，实际用户资料、真实视频取帧和真实模型输出尚待验收，因此当前不作为可分发版本的完成声明。

## 1. 目标与结论

高级笔记让用户把已保存的文章、视频字幕、指定时间的截图和已有普通笔记，整理成适合阅读与分享的图文笔记。它有两个入口：

1. **从已有笔记升级**：打开普通笔记，生成同一篇笔记的高级展示版。默认保留原文，也允许用户选择经核对的内容整理。
2. **从资料新建**：选择已保存的资料与截图，生成笔记草稿；用户编辑并确认后才保存，再生成高级展示版。

高级版是笔记的派生产物。笔记仍只有一条列表记录；标题、正文、文件夹、来源及笔记持有的截图附件是可编辑的主数据。版式、主题、HTML 和 PDF 可以重新生成。用户不需要维护两篇内容相近的笔记。

**推荐路线**：独立实现 GearNote 所需的内容整理和确定性排版，借鉴歸藏设计“同一内容、多种成品出口”和统一设计规则的思路。当前不直接集成 DeepSeek Harness 插件或其 AGPL 设计 skill。

## 2. 已核对的现状

| 领域 | 当前实现 | 对高级笔记的影响 |
| --- | --- | --- |
| 笔记 | src-tauri/src/notes.rs 的 Note 包含 title、body、sources、folder_id；正文在界面中以 textarea 编辑，保存至 SQLite 的 note_rows JSON；现有导出为 Markdown | 可以保留旧笔记结构及普通编辑流程；“正文已经是完整 Markdown 编辑器”并非现状 |
| 来源 | NoteSource 保存资料 ID、标题、网址、可选视频时间点；最多关联 20 个来源 | 足以定位来源资料，但不能单独记录每个结论对应的原句 |
| 资料检索 | db.rs 的 segment_fts 索引 record_segments；read_tools.rs 的 ReadIndex 只读取本轮已选且处理成功的 KnowledgeRecord | 普通笔记目前不会自动进入该索引，也不能直接充当 Agent 可引用资料；本功能不假设它已经具备这些能力 |
| 截图 | 聊天截图保存在应用数据目录的 chat-frames，消息中持有 image_id、record_id、at_seconds；删除所属会话会清理文件 | 笔记确认引用截图时必须复制为笔记自己的附件，不能只保存聊天图片 ID |
| Agent | 资料问答有搜索、读取、引用校验和深度视频模式；附带图片时当前资料探索路径关闭 | 图文笔记需要专用的有界组装流程，不能把“图片 + 任意资料”直接塞进现有 ask_agent 并假定工具会继续读资料 |
| 笔记修改 | workflow.rs 允许模型提出 1–3 处追加或唯一原文替换；用户确认后才写入 | 全文重新组织不能假装是现有提案的一个小改动；需要单独的草稿、差异预览、确认和旧版本保护 |
| 预览安全 | 生产 Tauri 配置已有 CSP，包含 frame-src 'none'；开发 CSP 单独设置 | iframe 预览的具体加载方式需要在实际 WebView 验证；不能照旧文档的 csp:null 假设修改 |

上述结论以代码为准。以前的方案中“笔记已经能被 segment_fts 搜索”“笔记已经能被 Agent 当资料引用”“生产 CSP 为空”等说法不适用于当前版本。

## 3. 产品边界

### 3.1 这次要完成

- 普通笔记可一键生成高级版，不改变笔记 ID、文件夹与原有来源。
- 新建笔记可从用户明确选中的资料与截图生成草稿。
- 原文美化可离线完成；内容整理需要已配置的模型服务。
- 高级版可预览、修改主题、查看图文来源，并导出可分享的成果。
- 所有生成内容先给用户核对；模型本身没有保存笔记、读取任意文件或执行命令的权限。
- 截图在笔记保存后不受聊天会话删除影响。
- 旧笔记 JSON 无新字段时仍能正常读取、编辑和导出。

### 3.2 暂不包含

- 网页 PPT、多张社交卡片批量生成、语气档案和“去 AI 味”工作流。
- 任意第三方 skill 加载、通用 Agent 循环、模型生成任意 HTML/CSS/JavaScript。
- 自动截取整段视频、自动读取未选资料、批量改写所有旧笔记。
- 把笔记接进现有资料全文索引或 Agent 参考工具；这可作为后续独立需求。
- 首版 PNG 长图和移动端编辑器。先保证阅读版预览与独立 PDF 的质量。

## 4. 用户流程

### 4.1 已有普通笔记升级

入口放在笔记编辑页，按钮文字为“生成高级版”。点击后进入一个可取消的预览流程：

1. 选择“原文美化”或“整理内容并排版”。默认“原文美化”。
2. 选择版式和主题，按需选择这篇笔记关联视频的指定时间截图，或选择当前会话已有截图。用户可以给图片写说明、调整位置。
3. 预览标题、段落层级、重点、图片、图注和来源。原文美化不调用模型，也不改变正文。
4. 点击“保存高级版”后，保存展示配置与选中的持久附件。普通笔记仍在原位置；可在“编辑 / 高级版”之间切换。

“整理内容并排版”会额外生成一份**正文修改草稿**。界面必须展示原文与新文差异，以及新增事实的来源。用户可以继续编辑草稿；确认时才更新同一篇笔记的正文，并保留更新前版本以便撤销。放弃草稿时，笔记原文、来源和附件不变。

无来源的旧笔记仍可原文美化。若要求模型整理，它只能重组或润色笔记已有文字；不得补出资料中不存在的新事实。用户可在流程中明确增加资料，新增来源仍需确认。

### 4.2 从资料和截图新建

用户从已保存的文章、视频或对话中进入“生成高级笔记”，明确勾选资料和截图。第一版只允许处理成功、用户已选择的资料；失败记录和演示资料不参与事实依据。

后台按现有资料边界取得原文片段。字幕结论保留命中的时间；截图保留所属视频、时间、图片 ID。模型返回标题和分节草稿，界面显示引用、图片与待核对的画面观察。用户可以删改、补充、选文件夹。点击“确认并保存”后才创建普通笔记及其高级版。

如果模型不支持视觉输入，截图仍可作为配图，图注由用户填写或仅显示来源与时间；系统不能声称已经“看懂画面”。如果只读到了部分字幕，应显示覆盖范围，不能声称总结了整条视频。

### 4.3 后续编辑与刷新

每个高级版记录其生成时对应的笔记版本。普通正文、来源或图片位置变化后，高级版显示“基于旧版本生成”，提供“按当前内容刷新”。旧导出文件可保留供用户查看，但默认展示最新笔记的普通正文；不静默覆盖已导出的文件。

旧笔记升级不会重复创建笔记，也不会改变现有笔记 ID。用户可以删除高级版并继续使用普通笔记。删除高级版不得删除正文和仍被笔记引用的截图附件。

## 5. 内容与引用规则

模型只返回**内容草稿和结构化版式建议**，例如标题、章节、段落、列表、图片位置与说明；HTML 和 CSS 由 GearNote 根据固定模板生成。

文本规则：

- 新写入的资料事实必须对应本轮真正读取过的片段，带资料 ID、片段编号和连续原句。服务端校验编号与原句是否存在，再交用户核对。原句校验只证明引文出现过，不保证结论在语义上必然成立。
- 旧笔记原文可以作为待整理的用户内容；不能自动伪装成已核实的外部来源。由原文推导出的新判断应明确标为待核对，或要求用户补充资料。
- 资料不足时生成明确的“待补充”项，不用无引用结论填满版面。
- 资料正文、字幕和截图里的提示词都作为数据处理，不能改变系统规则。
- 来源按钮可打开文章或定位视频时间。高级版的段落级引文另存为展示证据；现有 NoteSource 继续记录笔记级来源。

图片规则：

- 只允许用户明确选择的截图进入草稿。每张图都保留 image_id、record_id、at_seconds 与来源会话信息。
- 图片说明区分“用户填写”“字幕文字支持”“模型画面观察”。画面观察由用户核对；不得把画面当作含有可做文字子串校验的资料片段。
- 服务端校验图片属于允许的会话/资料、文件存在且大小和类型合格；模型不能通过给出路径引用本地任意文件。
- 用户确认保存时复制图片至笔记附件目录；聊天会话此后可独立删除。

## 6. 数据设计与生命周期

### 6.1 主数据与派生数据

继续把现有 Note 作为笔记主实体。正文保持可读、可导出的文本；高级版不存放模型生成的整页 HTML 作为唯一内容。建议增加两类旁表：

| 数据 | 建议内容 | 生命周期 |
| --- | --- | --- |
| note_assets | 附件 ID、note_id、原截图 ID、资料 ID、视频时间、MIME、相对路径、字节数、创建时间 | 笔记持有；会话删除不影响它 |
| note_renditions | 高级版 ID、note_id、模板、主题、生成所用笔记版本、段落级证据与图文位置、导出路径、创建时间 | 可重生成；不替代笔记正文 |

图片插入位置使用受控的附件标记或结构化块 ID；正文、预览和 Markdown 导出应共用同一套附件解析规则。Markdown 导出需同时处理图片文件，避免导出一篇含失效本机路径的笔记。

第一版每篇笔记可以只展示一个当前高级版，数据结构保留多个版本的可能。高级版的“过期”由当前笔记版本和生成时版本比较得出，不靠模型猜测。

### 6.2 保存过程

草稿期间不改动正式笔记。确认时：

1. 重新读取目标笔记，检查它与开始编辑时的版本一致；若已被其他窗口修改，停止并让用户重新预览。
2. 校验标题、正文长度、来源、截图归属和引用；复制附件到受控的暂存目录。
3. 在 SQLite 事务中写入笔记、附件记录和高级版元数据。文件最终落位与数据库提交之间需要失败清理；启动或删除时可清理孤儿暂存文件。
4. AI 整理旧笔记时，保存更新前版本及操作记录，提供明确的撤销入口。撤销时也应检查当前笔记是否又被编辑过。

所有文件路径存为相对应用数据目录的路径，并在读取时检查规范化路径仍位于授权目录内。应用数据与源码仓库分离；不使用真实用户数据库做自动化测试。

### 6.3 兼容与删除

- 旧 note_rows JSON 按现有字段读取。新增字段如有必要必须带默认值；新增旁表用可重复执行的迁移创建。
- 没有高级版的笔记照常编辑、保存和导出。
- 若笔记来源资料之后被删除，保留笔记里的标题/网址快照和已确认的图片，来源按钮显示“原资料已不存在”。
- 目前没有完整的笔记删除流程；将来新增删除时，先核对附件是否仍被其他对象引用，再清理所属产物和文件。

## 7. 排版、预览与导出

第一版采用一套“阅读型”模板与两种配色。布局重点是中文行宽、层级、留白、图片比例、图注和来源区；视觉样稿先用一篇真实笔记与一张真实截图检验。主题只改变预定义 token，不允许模型提交 CSS。

渲染器从受控的文本/块结构生成 HTML：

- 所有正文、标题、图注和 URL 按上下文转义；只接受允许的标记和本机附件引用。
- 不包含模型生成的 script、iframe、事件属性、远程脚本或外部字体请求。
- 预览若使用沙箱 iframe，需要先验证当前生产 CSP 的 frame-src 'none' 与 Tauri WebView 行为；仅作必要的最小调整，并加实际窗口测试。不得以关闭整个 CSP 解决预览。
- HTML 导出须连同图片一起可搬移；可以选择受控的自包含文件或带 assets 的文件夹。PDF 是优先的单文件分享格式。
- PDF 转换可先评估系统 Edge 的无界面打印，但必须检测可执行文件、设置超时、核对产物存在且有效，并在缺失时给出清楚错误。它不是“Windows 一定存在”的依赖。PNG 长图留到后续，避免首版把视口截图误当整页。

高级版导出与现有 Markdown 导出并存。没有配置模型时，原文美化、预览和导出仍可使用。

## 8. 权限、安全与第三方授权

- 模型不能直接调用 save_note、修改 note_rows、执行渲染命令或读取任意路径。模型只提出草稿；用户确认后，由固定 Tauri 命令完成写入。
- 出图程序由应用用固定程序和受控参数调用，不接受模型给出整条 shell 命令。
- 限制资料数、截图数、单图大小、总输入与输出大小；超限应在发送模型或生成文件前提示。
- 图片、字幕、笔记正文和外部网页内容都属于不可信输入。生成 HTML 时不依赖“模型应该不会写恶意代码”。
- 歸藏设计的插件与三个设计 skill 标注 AGPL-3.0；humanizer-zh 单独标注 MIT。GearNote 自有代码为 Apache-2.0。本计划借鉴交互与设计原则，首版不复制或打包其 AGPL 源码、样式或素材；将来若要引入，应按具体文件和发行方式重新核对许可证。[歸藏设计](https://github.com/op7418/dsh-guizang-design) · [Apache 兼容性说明](https://www.apache.org/licenses/GPL-compatibility.html)

## 9. 建议实现落点与调用契约

前端以 src/components/NotesPanel.tsx 为两个入口的共同落点，新建高级笔记预览组件，避免把生成、附件选择和导出逻辑继续堆进笔记编辑组件。src/notes.ts 定义草稿、附件和高级版的前后端类型；src/hooks/useNotes.ts 负责刷新笔记列表与处理确认后的状态；src/App.tsx 只连接页面和回调。

后端可以新增独立的高级笔记模块，负责草稿状态、附件归属、确认写入与渲染。src-tauri/src/db.rs 增加旁表和临时目录测试；src-tauri/src/notes.rs 保持现有普通笔记命令兼容；src-tauri/src/lib.rs 注册新命令。模型生成复用现有配置、已选资料读取和引用校验组件，必要时把校验提取为可复用的内部函数，保持现有问答规则不变。指定时间截帧继续调用既有本地能力，不增加模型命令工具。

建议采用下列命令边界，实际命名以代码审查时确定：

| 操作 | 输入 | 结果与副作用 |
| --- | --- | --- |
| 准备高级版草稿 | 可选 note_id、明确选中的资料 ID、截图 ID、模式 | 返回可预览草稿；不写正式笔记 |
| 预览高级版 | 草稿内容、模板和主题 | 返回安全的预览内容；不写正式笔记 |
| 确认高级版 | 草稿 ID、用户修改后的内容、目标笔记版本 | 校验后写笔记、持久附件和高级版记录 |
| 读取与刷新高级版 | note_id、高级版 ID | 返回当前或过期状态；刷新须由用户触发 |
| 导出高级版 | 高级版 ID、允许的格式 | 在受控目录生成文件并返回路径 |

草稿 ID 只标识这次待确认内容，不是授权令牌。每次确认仍要重新检查当前笔记、资料和截图归属；客户端不能自行提交任意文件路径。界面在生成、预览、确认、导出四种忙碌状态下禁用重复操作，并清楚保留失败前的可编辑草稿。

首版建议沿用现有每篇笔记最多 20 个来源的上限，再给单次生成设置较小的资料、截图与输出预算。预算以实际字符、图片字节和模型请求上限分别计算，不把字符数称作 token，也不默许大图无限塞进请求。具体数值在阶段 0 的真实样稿和阶段 3 的真实模型探针后固定，并写入测试。

## 10. 分阶段实施与完成线

### 阶段 0：真实样稿

用一篇现有笔记、一段真实字幕和一张已截的图制作静态样稿。检查长文阅读、图片比例、来源区、A4 分页和小窗口宽度。确定首版模板与主题；样稿中的用户资料不提交仓库。

**完成线**：用户能看到并评价具体页面；视觉方向、长文与图片排版有明确结论。

### 阶段 1：旧笔记原文美化

实现受控渲染、主题预览和同一篇笔记的高级版记录。原文美化不调用模型。旧数据迁移与“正文修改后高级版过期”一起完成。

**完成线**：旧笔记可一键预览/保存高级版，正文和来源不变；取消不写入；旧笔记照常打开；恶意标记只作为文字显示。

### 阶段 2：截图成为笔记附件

实现用户选择已有截图或主动指定视频时间截图、归属校验、确认时持久复制、图注和位置编辑、Markdown 导出中的附件处理。

**完成线**：笔记保存后删除原聊天会话，图片仍可显示和导出；未确认、失败或无权引用的截图不进入正式笔记。

### 阶段 3：资料生成与旧笔记整理

新增有界的图文笔记草稿流程，复用已选资料的读取和引文校验边界。旧笔记可选择“整理内容并排版”；生成完整差异预览，确认后才更新正文，保留可撤销版本。模型不支持视觉时只插入图片，不做画面事实推断。

**完成线**：无出处的新事实不进入已确认笔记；来源定位和视频时间正确；旧笔记整理可放弃、可确认、可在未发生后续修改时撤销；并发修改不会被覆盖。

### 阶段 4：分享导出与回归

完成 HTML/附件导出和 PDF 导出，检查长文分页、中文字体、图片清晰度与文件大小。测试 Windows 试用包里的运行路径；PNG 作为独立后续需求。

**完成线**：导出文件在另一台 Windows 电脑上可查看；缺少导出依赖时有明确错误；现有笔记、资料问答、截图指令和 Markdown 导出无回归。

每阶段结束运行相关 Rust 测试与 npm run build；涉及实际预览或导出的阶段还需在正式 Tauri 窗口检查。使用临时目录数据库和测试图片，不读取或改写真实用户数据。

## 11. 关键测试清单

- 旧笔记 JSON 无高级版字段时能读取；原文美化不更改 title/body/sources/folder_id。
- 预览、模型失败和用户取消均不写入正式笔记或附件目录。
- AI 草稿中的来源编号错误、原句不在已读片段、图片不属于允许会话或资料时拒绝确认。
- 画面观察与字幕引文分开显示；无视觉模型时不声称识别了画面。
- 删除原会话后，笔记图片仍可显示；笔记附件路径不能越出应用数据目录。
- 保存期间笔记被另一窗口改动时拒绝覆盖；刷新或撤销不会抹掉后续修改。
- 输入包含 HTML 标签、事件属性、脚本协议和异常图片地址时，预览与导出仍只显示允许内容。
- 普通笔记保存、原有修改提案、资料检索、深度视频模式、引用校验和 Markdown 导出继续通过现有回归测试。

## 12. 成功标准与后续选择

第一版成功的判断标准是：旧笔记能稳定升级为可读的高级版；新笔记能带着准确来源和持久截图生成；用户始终能看见并控制正文变化；导出的 PDF 在其他电脑上仍完整。不要用“主题数量”或“模型生成 HTML 的复杂程度”代替这些标准。

如果用户确实经常把笔记分享出去，再评估多主题、卡片、PNG 长图和 PPT。若只是自己阅读，优先改进笔记检索、编辑和排版，而不扩展成独立的设计工作室。
